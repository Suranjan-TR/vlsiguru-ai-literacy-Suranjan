# Week 02 - Final Reflection

## 1. Which ML concept became clearest to you this week, and what helped you understand it?

The difference between learning approaches and ML task types became clearer to me. Supervised learning uses labelled examples, while unsupervised learning finds patterns without predefined labels. Classification predicts categories, whereas regression predicts numerical values. Comparing examples and creating tables helped me understand these differences.

## 2. Which two concepts are easy to confuse? Explain how you now distinguish them.

I initially found it easy to confuse learning paradigms with task types. A learning paradigm explains how a model learns, while a task type explains what the model is expected to do. For example, supervised learning can be used for classification or regression.

I also learned that training and inference are different. Training is the process of learning from data, while inference uses the trained model to make predictions on new inputs.

## 3. What is one claim you checked against a reliable source, and what did the source establish?

I checked Google's Machine Learning Crash Course resources about training and test datasets. They helped me understand that training data is used to learn patterns, validation data helps compare and tune models, and test data is used for final evaluation. Keeping test data separate helps provide a more reliable estimate of how the model performs on unseen data.

## 4. Which stage of the ML lifecycle do you think is easiest to underestimate, and why?

I think data preparation is one of the easiest stages to underestimate. A model depends on the quality of the data used to train it. Missing values, incorrect labels, noisy measurements and unrepresentative data can lead to unreliable predictions. Even a good learning algorithm may perform poorly when the data is unsuitable.

## 5. What is one question you want answered before moving into deep learning?

I want to understand how neural networks learn their parameters and how their performance improves during training. I would also like to learn how deep learning can be applied to Design Verification, especially for test selection and functional coverage closure.

## Conclusion

This week helped me understand the basic concepts of Machine Learning, including data, learning approaches, task types, model training, evaluation and failure modes. I also learned that ML is not always the best solution and that a simple rule-based approach may be sufficient for some problems.

As a Design Verification learner, I am interested in understanding how ML can assist verification engineers while keeping simulation, functional coverage, assertions and engineering judgement important.
